# Reviewed workload command driver

The existing request-execute backend now recognizes reviewed workload plans.
Owner HTTP/CLI and permitted origin commands share that backend. Exact retained
command retries return the existing receipt; they never create another issuer,
offer, source, lease or stop attempt. Node-origin execution rechecks disclosure.

Before new issuance, the coordinator inspects a fresh credential/TLS connection,
registered workload runtime/capability, enabled policy bounds and stop support.
It checks the exact source/resource/adapter snapshot, applied microphone permission,
local listening consent and configured Python, then verifies the same session
again. These are readiness snapshots, not proof that a physical device works.
The existing engine-owned issuer reserves its lifetime before asynchronous
issuance. Response inspection retains the original issuance observation deadline.

The driver moves that original issuer once into the existing engine lifetime.
Preparing its bounded network route sends nothing. The actual offer enqueue and
each lease enqueue share the same short control gate as owner stop/shutdown.
The prepared route and incoming frames must retain the original authenticated
issuer/session/node/runtime. Payload fields cannot substitute those identities.
The consumed ACK must be durably saved before renewal two. Cancellation, failed
storage, source rejection, disconnect or original deadline retires the issuer;
no detached renewal task, replacement session or automatic migration is created.

Executable source readiness uses snapshot schema three with
`execution_available: true`; it still forbids capture/authorization claims and
requires every local readiness condition. Existing schema-two snapshots remain
read-only, unavailable inspection data and cannot start work. The current node
service continues to return that old form until its production integration is
accepted; registration metadata alone cannot override an unavailable snapshot.

Metadata events use the existing bounded native journal writer. Their original
network byte/count charges stay held through save observation and notification.
The driver can service lease frames while event saves run; a full queue refuses
rather than buffering indefinitely. Stop drops event observers before beginning
the existing one-attempt stop-delivery path. Native storage retains its actual
slot/journal ownership until exit. It receives no issuer, lease proof or source.
Notifications follow confirmed persistence and do not depend on the dashboard.

The existing execution record adds an optional observations prefix. Empty prefixes
retain old schema-two/three/four history; records containing events use schema five.
Definition-bound canonical prefix/count/byte checks apply, and retained events
cannot be replaced, removed or extended after retirement. Completion checks the
exact saved prefix before closing the original issuer window. Historical hashes
and reported exit fields cannot manufacture node-local owned-source evidence.
Job detail commands expose total count and at most eight recent metadata events.

Eight new regressions cover journal prefix/completion integrity, cancellation under
real storage contention, stop notification and evidence preservation, current
session readiness, prepared-offer dispatch, and metadata budgets. A genuine
credential/pinned-TLS synthetic peer exercises owner HTTP start, durable ACK before
renewal two, event persistence, completion, explicit stop, disconnect and idempotent
retry. Its synthetic receipts do not prove real node source execution. The new
tests await full changed-source hosted verification.

Production nodes still advertise no continuous execution. Full NodeClient source
execution over credential/TLS, truthful capability refresh after policy changes,
physical two-PC/long-source acceptance and final main/release checks remain open.
The earlier Windows reserved-capture deadline failure is unresolved. No release,
installed app/node, permissions, model, version, feed or security policy changes
are included in this increment.
